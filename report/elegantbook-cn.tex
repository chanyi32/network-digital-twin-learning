\chapter{研究背景与意义}

面向 6G 网络业务多样化、资源异构化、网络自治化和服务化演进趋势，传统基于人工经验和离线仿真的网络管理方式难以满足低时延、高可靠、可解释和低成本试错需求。网络数字孪生通过构建与物理网络实时交互映射的虚拟网络体，为意图理解、智能决策、策略预验证和闭环编排提供可信环境。本文围绕 6G 意图驱动智能决策、网络高精度孪生建模及编排等关键技术，系统分析技术背景、总体架构、关键机制、挑战与演进方向。

\section{6G 网络演进趋势}

随着 5G 网络规模化部署和垂直行业应用不断深化，移动通信网络正从“以连接为中心”的通信基础设施，逐步演进为“连接、感知、计算、智能、安全”深度融合的新型数字基础设施。预计 2030 年及以后，6G 网络将进一步承载沉浸式通信、通感一体化、工业互联网、车联网、低空经济、空天地一体网络、智能制造、智慧城市等多样化业务需求，其网络形态、能力边界和服务模式都将发生深刻变化。


在此过程中，人工智能将不再只是外部辅助工具，而是逐步嵌入无线接入、核心网、承载网、边缘云和终端等多个网络环节，成为网络设计、运行、优化和演进的内生能力。通过 AI 原生化，网络可以实现流量预测、资源调度、干扰协调、故障识别、能耗优化和用户体验保障等智能功能。未来网络将不只是被动承载业务，而是能够根据业务状态和环境变化进行主动感知、主动分析和主动优化。


此外，未来网络能力将以更加模块化、云原生化和服务化的方式组织，通信、感知、计算、数据、智能、安全和编排等能力可以通过标准化接口和 API 向上层应用开放。网络不再只是提供连接服务，而是逐步演进为可调用、可组合、可编排的新型能力平台。面向差异化行业需求，6G 网络需要支持按需定制、灵活编排和动态调整，以适配不同业务在时延、可靠性、带宽、能耗和安全等方面的差异化要求。


这些趋势使未来网络具备更强能力的同时，也对网络感知、建模、决策、验证和编排提出了更高要求，为意图驱动智能决策、网络高精度孪生建模和自动化编排控制等关键技术的发展奠定了需求基础。

\section{传统网管方式局限}

面向 5G 及以前的移动通信网络，网络规划、建设、维护和优化主要依赖人工经验、规则配置、离线仿真和现网验证等方式。在网络规模相对可控、业务类型相对稳定的阶段，这类方法能够满足基本运维需求。但随着 6G 网络向泛在智能、通感算智融合、服务化架构和端到端自治方向演进，传统网络管理方式逐渐难以适应未来网络的复杂性和动态性。


经验驱动难以支撑复杂网络管理。传统网络优化高度依赖专家经验，运维人员通常根据 KPI、告警、用户投诉和路测结果进行问题定位与参数调整。然而，6G 网络中的管理对象将从传统网元、链路和小区扩展到频谱、波束、算力、模型、切片、业务意图和用户体验等多维要素。网络状态空间显著扩大，人工方式难以及时、全面地识别多因素之间的耦合关系，也难以满足实时或准实时闭环优化要求。


参数配置方式难以支撑意图驱动管理。传统网络管理以底层参数配置为主，例如小区发射功率、切换门限、邻区关系、路由策略和切片资源比例等。该方式要求运维人员将业务目标人工转换为具体网络参数。但在 6G 场景下，用户需求往往表现为高层业务意图，例如“保障工业控制低时延高可靠”“提升热点区域用户体验”“在不影响 SLA 的前提下降低能耗”。传统方式缺少从业务意图到网络策略的自动映射机制，难以实现从意图到配置的自动转换。

\section{意图驱动网络价值}

意图驱动网络（Intent-Based Networking, IBN）是面向 6G 自智网络的重要管理模式。其核心思想是将网络管理方式从“人工配置参数”转变为“用户表达目标、系统自动生成策略”。也就是说，用户或业务系统不再直接指定小区功率、切换门限、路由路径、切片资源比例等底层配置，而是提出高层业务目标，例如“保障某区域低时延业务”“提升热点区域用户体验”“降低夜间网络能耗”等，由系统自动完成意图解析、策略生成、孪生验证。


6G 网络涉及无线、承载、核心网、边缘云、算力和业务平台等多个网络域，底层参数数量庞大，人工直接配置难度较高。通过意图驱动机制，运维人员只需关注业务目标，系统自动完成目标分解和策略映射，从而降低人工配置复杂度。传统网络优化往往需要人工分析 KPI、告警、用户投诉和业务需求，再手动制定优化方案。意图驱动网络可以结合 AI、知识图谱和规则推理技术，将业务目标快速转换为可执行策略。例如，“保障工业控制业务低时延高可靠”可被转换为时延、可靠性、资源隔离、调度优先级和边缘算力部署等约束条件，并进一步生成网络配置策略。

\section{网络数字孪生支撑}

网络数字孪生（Network Digital Twin, NDT）是支撑6G网络智能化、自治化和服务化演进的重要技术基础。其核心思想是在数字空间中构建与物理网络实时映射、动态交互的虚拟网络体，通过数据采集、模型构建、状态同步、仿真推演和闭环反馈，实现对物理网络状态、行为和性能的分析、预测、验证与优化。与传统网络仿真不同，网络数字孪生不仅能够描述网络当前运行状态，还能够基于实时数据和高精度模型预测未来网络变化，并在虚拟环境中评估不同控制策略可能产生的影响。因此，网络数字孪生可作为6G网络智能决策的重要验证平台，为策略生成、优化选择和风险评估提供可信依据。


网络数字孪生是实现意图驱动闭环优化的重要支撑。意图驱动网络负责理解业务目标，并将其转换为可执行的网络策略，而数字孪生负责在策略作用于物理网络之前，对策略效果进行预验证。其中，业务意图经过解析后形成网络优化目标和候选策略，随后将候选策略加载至数字孪生环境中，通过仿真推演评估其对网络性能、业务体验和资源消耗的影响。只有满足SLA约束和优化目标的策略，才进一步作用于物理网络。具体而言，网络数字孪生在意图驱动闭环中主要承担以下作用：

（1）网络状态镜像：通过实时采集物理网络中的拓扑、性能、业务和资源数据，实现虚实网络状态同步，为智能决策提供准确环境信息；

（2）策略预验证：在数字空间中模拟候选策略执行过程，分析其对时延、可靠性、吞吐量、能耗等指标的影响，降低直接在现网试错带来的风险；

（3）模型动态校准：根据物理网络执行结果持续更新孪生模型，提高数字空间与真实网络之间的一致性；

因此，网络数字孪生并不是简单复制物理网络，而是构建连接“业务意图—智能决策—策略验证—网络优化”的虚拟闭环环境，为6G网络实现自主感知、自主决策和自主优化提供关键技术支撑。

\chapter{总体架构与技术体系}
\label{chap:overall_architecture}

面向6G网络业务多样化、资源异构化和网络自治化的发展需求，
本文围绕“意图驱动智能决策”和“网络高精度孪生建模与编排”两项关键技术，
构建总体技术架构。
该架构以业务意图为输入，
以当前RAN网络状态为基础，
通过意图理解、目标转译、候选策略生成、
孪生场景构建、策略推演验证和结果反馈，
形成从业务需求表达至策略验证优化的完整处理链路。

\section{总体架构}

总体架构如图\ref{fig:overall_architecture}所示。
其中，上层为业务意图输入，
中间包括意图驱动智能决策模块和网络高精度孪生建模与编排模块，
底层为物理RAN网络及其状态数据。
两类关键技术通过“候选策略”这一中间对象实现衔接：
意图驱动智能决策负责根据业务目标生成候选策略，
网络数字孪生负责在策略作用于物理网络之前完成推演、验证与评估。

\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.8\textwidth]{framework.png}
    \caption{总体技术架构}
    \label{fig:overall_architecture}
\end{figure}

从功能流程看，
本文的整体技术链路可概括为：

\begin{equation}
\text{Intent}
\rightarrow
\text{SLA}
\rightarrow
\text{Candidate Policy}
\rightarrow
\text{Twin Scenario}
\rightarrow
\text{Validation Result}
\label{eq:overall_flow}
\end{equation}

其中，
\textit{Intent}表示用户或业务系统提出的高层业务目标，
\textit{SLA}表示量化后的业务需求与约束，
\textit{Candidate Policy}表示面向RAN生成的候选策略，
\textit{Twin Scenario}表示针对候选策略构建的数字孪生验证场景，
\textit{Validation Result}表示经过性能推演、约束检查和综合评分后得到的策略验证结果。

意图驱动智能决策模块主要解决“如何从业务目标生成候选策略”的问题。
它以业务意图为输入，
通过业务意图抽取识别时间范围、空间范围、目标业务和约束条件等关键信息，
再通过业务意图转译将高层需求映射为可计算的网络目标和SLA约束，
最后结合当前RAN状态生成候选策略，
为后续验证提供输入。
该部分内容将在第三章中展开。

网络高精度孪生建模与编排模块主要解决“如何对候选策略进行验证”的问题。
它以当前RAN状态和候选策略为输入，
构建与物理网络对应的孪生状态，
并将候选策略映射为独立的孪生验证场景，
随后调用性能模型完成策略推演、
约束检查与评分排序，
输出策略可行性、效果评估和诊断信息。
该部分内容将在第四章中展开。

需要说明的是，
当前研究重点面向单小区RAN场景，
已完成候选策略生成、孪生场景构建和前向验证流程；
而实时状态同步、模型在线校准、
残差修正和多轮反馈优化等能力，
将在后续研究中进一步增强。

\chapter{意图驱动智能决策技术}
\label{chap:intent_driven_decision}

意图驱动智能决策是实现网络自动化和自智化管控的重要技术环节。
其基本思想是以用户或业务系统提出的高层业务目标为输入，
自动完成业务语义理解、网络目标转译、候选策略生成和策略效果评估，
从而减少传统网络管理对人工配置和运维经验的依赖。

与直接面向设备参数的控制方式不同，
意图驱动决策首先描述用户希望网络达到的业务效果，
而不是直接指定需要修改的无线参数。
例如，用户可以提出如下需求：

\begin{quote}
“今晚演唱会期间，保障体育场内视频用户的上行体验，
尽量减少能耗，同时不影响语音业务。”
\end{quote}

上述需求同时包含视频业务保障、RAN节能优化和语音业务保护，
但没有直接给出策略生效时间、目标小区、无线资源配置、
调度权重和业务质量门限。
因此，需要将自然语言需求逐步转换为RAN侧可识别、
可计算和可评估的候选网络策略。

本文面向单小区无线接入网
（Radio Access Network, RAN），
构建从业务意图抽取到候选策略评估的决策原型。
当前研究不涉及承载网、核心网、多小区协同和真实设备配置下发。


\section{总体决策流程}
\label{sec:intent_decision_overview}

本文将意图驱动智能决策划分为业务意图抽取、
业务意图转译、网络策略生成和候选策略评估四个主要环节。
其总体处理过程可表示为：

\begin{equation}
\begin{aligned}
\text{Business Requirement}
&\xrightarrow{\mathrm{Intent\ Extraction}}
I_{\mathrm{ext}}
\xrightarrow{\mathrm{Intent\ Translation}}
I_{\mathrm{trans}}^{\mathrm{RAN}}
\\
&\xrightarrow{\mathrm{Policy\ Generation}}
\mathcal{P}^{(0)}
\xrightarrow{\mathrm{Policy\ Evaluation}}
\mathcal{S}^{(0)}
\xrightarrow{\mathrm{Feedback}}
\mathcal{P}^{(1)},
\end{aligned}
\label{eq:intent_decision_pipeline}
\end{equation}

其中：

\begin{itemize}
    \item $I_{\mathrm{ext}}$表示从自然语言中抽取的结构化业务意图；
    \item $I_{\mathrm{trans}}^{\mathrm{RAN}}$表示RAN作用范围、
    网络目标和SLA约束；
    \item $\mathcal{P}^{(0)}$表示初始候选RAN策略集合；
    \item $\mathcal{S}^{(0)}$表示候选策略的性能、约束和评分结果；
    \item $\mathcal{P}^{(1)}$表示根据评估反馈生成的改进策略集合。
\end{itemize}

四个环节之间具有明确的递进关系：

\begin{enumerate}[label=\arabic*)]
    \item 业务意图抽取识别用户表达的时间、地点、
    业务对象、目标和约束；
    \item 业务意图转译补全活动时间、目标小区、
    RAN目标和SLA门限；
    \item 网络策略生成将RAN目标映射为动作模板和参数组合；
    \item 候选策略评估结合当前RAN状态计算策略性能，
    完成约束检查、评分排序和反馈改进。
\end{enumerate}

本文各模块的实际实现方法为：

\begin{equation}
\boxed{
\begin{aligned}
&\text{规则驱动的业务意图抽取},\\
&\text{静态知识驱动的业务意图转译},\\
&\text{模板与离散参数驱动的策略生成},\\
&\text{简化RAN模型驱动的策略评估},\\
&\text{基于局部邻域搜索的反馈优化}.
\end{aligned}
}
\label{eq:implemented_decision_methods}
\end{equation}

候选策略评估结果不仅用于选择较优策略，
还可以反馈至策略生成过程。
设第$n$轮候选策略集合为$\mathcal{P}^{(n)}$，
其评估结果为$\mathcal{F}^{(n)}$，
则下一轮策略生成过程为：

\begin{equation}
\mathcal{P}^{(n)}
\xrightarrow{\mathrm{Evaluation}}
\mathcal{F}^{(n)}
\xrightarrow{\mathrm{Local\ Feedback}}
\mathcal{P}^{(n+1)}.
\label{eq:policy_feedback_loop}
\end{equation}

评估反馈主要包括视频吞吐率不足、视频时延过高、
语音质量下降、PRB利用率过高和能耗偏高等信息，
系统据此调整相邻参数档位或动作组合。


\section{业务意图抽取}
\label{sec:business_intent_extraction}

业务意图抽取是意图驱动决策的起始环节，
其目标是从自然语言需求中识别业务类型、
作用范围、目标对象、保障目标和保护约束，
并形成统一的结构化业务意图。

对于如下需求：

\begin{quote}
“今晚演唱会期间，保障体育场内视频用户的上行体验，
尽量减少能耗，同时不影响语音业务。”
\end{quote}

系统需要识别：

\begin{itemize}
    \item 时间表达“今晚演唱会期间”；
    \item 空间表达“体育场内”；
    \item 目标对象“视频用户”；
    \item 保障目标“上行体验”；
    \item 优化目标“减少能耗”；
    \item 保护对象“语音业务”；
    \item 视频保障、节能优化和语音保护之间的逻辑关系。
\end{itemize}

本阶段只提取用户明确表达的业务语义，
不负责确定演唱会准确时间、目标小区、
SLA门限和RAN控制参数。

业务意图抽取结果表示为：

\begin{equation}
I_{\mathrm{ext}}
=
\left\{
T,L,O,S,G,C,R,U
\right\},
\label{eq:structured_intent_representation}
\end{equation}

其中：

\begin{itemize}
    \item $T$表示时间表达；
    \item $L$表示空间表达；
    \item $O$表示意图作用对象；
    \item $S$表示目标业务；
    \item $G$表示保障目标和优化目标；
    \item $C$表示业务保护约束；
    \item $R$表示语义关系和逻辑关系；

\end{itemize}

\subsection*{规则驱动的意图抽取}

本文采用有序正则表达式、领域关键词、
规范化词典和Schema校验完成意图抽取。

抽取过程表示为：

\begin{equation}
I_{\mathrm{ext}}
=
f_{\mathrm{rule}}
\left(
x;
\mathcal{R},
\mathcal{K},
\mathcal{D}
\right),
\label{eq:rule_based_intent_extraction}
\end{equation}

其中：

\begin{itemize}
    \item $x$表示原始自然语言文本；
    \item $\mathcal{R}$表示正则表达式和关系规则集合；
    \item $\mathcal{K}$表示领域关键词集合；
    \item $\mathcal{D}$表示术语规范化词典。
\end{itemize}

实际处理过程可表示为：

\begin{equation}
\begin{aligned}
x
&\xrightarrow{\mathrm{Normalization}}
x'
\xrightarrow{\mathrm{Regex/Keyword\ Matching}}
M
\\
&\xrightarrow{\mathrm{Intent\ Detection}}
C_I
\xrightarrow{\mathrm{Slot\ Construction}}
E
\\
&\xrightarrow{\mathrm{Relation\ Construction}}
R
\xrightarrow{\mathrm{Missing\ Check}}
U
\xrightarrow{\mathrm{Schema\ Validation}}
I_{\mathrm{ext}}.
\end{aligned}
\label{eq:intent_extraction_flow}
\end{equation}

首先对文本进行空白和标点规范化，
随后按照预设顺序匹配：

\begin{itemize}
    \item 时间和地点表达；
    \item 视频和上行业务表达；
    \item 保障类关键词；
    \item 节能和降低能耗关键词；
    \item 语音业务关键词；
    \item 保护、不得影响等约束表达；
    \item “尽量”“同时”等修饰关系。
\end{itemize}

业务保障标签的生成规则可抽象为：

\begin{equation}
c_{\mathrm{assurance}}
=
\mathbb{I}
\left[
m_{\mathrm{assure}}
\land
\left(
m_{\mathrm{video}}
\lor
m_{\mathrm{uplink}}
\right)
\right],
\label{eq:service_assurance_detection}
\end{equation}

节能标签表示为：

\begin{equation}
c_{\mathrm{energy}}
=
\mathbb{I}
\left[
m_{\mathrm{energy}}
\right],
\label{eq:energy_intent_detection}
\end{equation}

业务保护标签表示为：

\begin{equation}
c_{\mathrm{protection}}
=
\mathbb{I}
\left[
m_{\mathrm{voice}}
\land
m_{\mathrm{protect}}
\right].
\label{eq:protection_intent_detection}
\end{equation}

其中，
$m_{\mathrm{assure}}$、$m_{\mathrm{video}}$、
$m_{\mathrm{uplink}}$、$m_{\mathrm{energy}}$、
$m_{\mathrm{voice}}$和$m_{\mathrm{protect}}$
表示对应规则是否命中。

若文本不能触发任何受支持的意图标签，
系统不生成不确定结果，
而是返回不支持的意图错误。

在完成槽位构造后，
系统进一步生成以下语义关系：

\begin{equation}
\operatorname{Assure}
\left(
\texttt{video\_uplink\_experience}
\right),
\end{equation}

\begin{equation}
\operatorname{Minimize}
\left(
\texttt{ran\_energy}
\right),
\end{equation}

\begin{equation}
\operatorname{Protect}
\left(
\texttt{voice\_service}
\right).
\end{equation}

时间和地点分别形成意图的时间范围和空间范围。
同时，根据“尽量”“同时”和“不影响”等表达，
构造主要目标、软优化目标和强制约束之间的关系：

\begin{equation}
\begin{aligned}
R
=
\{
&\operatorname{Primary}
(\texttt{video\_uplink\_assurance}),
\\
&\operatorname{SoftObjective}
(\texttt{ran\_energy\_optimization}),
\\
&\operatorname{HardConstraint}
(\texttt{voice\_service\_protection})
\}.
\end{aligned}
\label{eq:intent_logical_relationship}
\end{equation}

当前抽取过程是确定性的，
不调用在线大语言模型或训练型自然语言处理模型。


\subsection*{缺失信息检测}

自然语言业务需求通常只描述业务方向，
无法直接提供网络执行所需的全部字段。
因此，本文采用Schema和规则检查，
显式生成待解析项集合：

\begin{equation}
U
=
\left\{
u_j
\mid
\operatorname{Required}(u_j)
\land
\neg\operatorname{Resolved}(u_j)
\right\}.
\label{eq:unresolved_item_set}
\end{equation}

对于演唱会业务需求，
主要待解析项包括：

\begin{itemize}
    \item \texttt{exact\_time\_period}：
    演唱会准确开始时间和结束时间；
    \item \texttt{ran\_scope}：
    体育场对应的目标小区和载波；
    \item \texttt{video\_service\_identification}：
    视频用户和视频业务的RAN侧识别规则；
    \item \texttt{uplink\_experience\_slo}：
    上行体验对应的吞吐率、时延和统计口径；
    \item \texttt{voice\_protection\_threshold}：
    语音业务质量门限和允许下降幅度；
    \item \texttt{objective\_weights}：
    业务、节能、资源和风险评分之间的权重。
\end{itemize}

准确活动时间和RAN作用范围由下一阶段的业务意图转译模块解析。
即使原文包含“今晚演唱会期间”和“体育场内”，
意图抽取器也只保留其原始语义，
不会自行计算具体时间或选择目标小区。

待解析项分为阻断项和非阻断项。
阻断项未解决时不能进入策略生成阶段；
非阻断项可以由配置文件提供默认值，
但需要保留其信息来源。

\section{业务意图转译}
\label{sec:business_intent_translation}

业务意图抽取阶段已经识别出时间表达、空间表达、
目标对象、保障目标、节能目标和语音保护约束，
但这些信息仍然属于业务语义，
不能直接作为RAN策略生成模块的输入。

例如，“今晚演唱会期间”尚未给出准确起止时间，
“体育场内”尚未确定目标小区，
“保障视频用户上行体验”也尚未转换为具体的吞吐率、
时延和用户达标比例要求。

因此，业务意图转译需要将结构化业务语义转换为
RAN侧可识别和可计算的作用范围、网络目标和SLA约束。
其处理过程可表示为：

\begin{equation}
I_{\mathrm{ext}}
\longrightarrow
S_{\mathrm{RAN}}
\longrightarrow
G_{\mathrm{RAN}}
\longrightarrow
C_{\mathrm{SLA}}
\longrightarrow
I_{\mathrm{trans}}^{\mathrm{RAN}},
\label{eq:intent_translation_reduced}
\end{equation}

其中，
$I_{\mathrm{ext}}$表示业务意图抽取结果，
$S_{\mathrm{RAN}}$表示RAN作用范围，
$G_{\mathrm{RAN}}$表示RAN目标集合，
$C_{\mathrm{SLA}}$表示SLA和无线资源约束，
$I_{\mathrm{trans}}^{\mathrm{RAN}}$表示转译后的RAN意图。


\subsection*{RAN作用范围解析}

本文采用静态事件库和场馆—小区映射库，
确定策略生效时间和目标RAN对象。
具体映射过程为：

\begin{equation}
\text{时间与活动语义}
\rightarrow
\text{事件记录}
\rightarrow
\text{场馆}
\rightarrow
\text{目标小区}.
\label{eq:scope_resolution_chain}
\end{equation}

首先，根据原始文本中的“演唱会”等活动语义，
在静态事件库中查询对应活动记录。
设匹配到的事件集合为$\mathcal{E}_{\mathrm{match}}$，
本文要求事件记录唯一：

\begin{equation}
\left|
\mathcal{E}_{\mathrm{match}}
\right|
=
1.
\label{eq:unique_event_requirement}
\end{equation}

当事件记录唯一匹配时，
系统获得演唱会的准确开始时间和结束时间：

\begin{equation}
T_{\mathrm{event}}
=
\left[
T_{\mathrm{start}},
T_{\mathrm{end}}
\right].
\label{eq:event_time_scope}
\end{equation}

为支持策略预部署和活动结束后的恢复，
系统在活动时间基础上增加前后生效窗口：

\begin{equation}
T_{\mathrm{effective,start}}
=
T_{\mathrm{start}}
-
\Delta T_{\mathrm{pre}},
\label{eq:policy_effective_start}
\end{equation}

\begin{equation}
T_{\mathrm{effective,end}}
=
T_{\mathrm{end}}
+
\Delta T_{\mathrm{post}},
\label{eq:policy_effective_end}
\end{equation}

其中，
$\Delta T_{\mathrm{pre}}$表示策略提前生效时间，
$\Delta T_{\mathrm{post}}$表示活动结束后的观察与恢复时间，
二者均由配置文件提供。

事件记录同时包含场馆标识。
系统根据场馆—小区映射库，
将场馆映射为gNB、小区和载波：

\begin{equation}
VenueId
\rightarrow
gNBId
\rightarrow
CellId
\rightarrow
CarrierId.
\label{eq:venue_ran_mapping}
\end{equation}

本文当前限定为单小区RAN场景，因此要求：

\begin{equation}
\left|
\mathcal{C}_{\mathrm{target}}
\right|
=
1,
\label{eq:single_cell_scope}
\end{equation}

其中，
$\mathcal{C}_{\mathrm{target}}$表示目标小区集合。

根据意图抽取阶段得到的视频业务和语音业务槽位，
系统进一步生成目标用户规则：

\begin{equation}
Rule_{\mathrm{video}}
=
\texttt{uplink\_video},
\qquad
Rule_{\mathrm{voice}}
=
\texttt{voice}.
\label{eq:translated_user_rules}
\end{equation}

因此，RAN作用范围可表示为：

\begin{equation}
S_{\mathrm{RAN}}
=
\left\{
T_{\mathrm{effective}},
VenueId,
gNBId,
CellId,
CarrierId,
Rule_{\mathrm{video}},
Rule_{\mathrm{voice}}
\right\}.
\label{eq:ran_scope_result}
\end{equation}


\subsection*{RAN目标与SLA约束映射}

根据结构化意图中的三类意图标签，
本文生成视频业务保障、RAN节能和语音业务保护三类目标：

\begin{equation}
G_{\mathrm{RAN}}
=
\left\{
G_{\mathrm{video}},
G_{\mathrm{energy}},
G_{\mathrm{voice}}
\right\}.
\label{eq:translated_ran_objectives}
\end{equation}

其中：

\begin{equation}
G_{\mathrm{video}}
=
\texttt{video\_uplink\_assurance},
\label{eq:video_assurance_objective}
\end{equation}

\begin{equation}
G_{\mathrm{energy}}
=
\texttt{ran\_energy\_optimization},
\label{eq:energy_optimization_objective}
\end{equation}

\begin{equation}
G_{\mathrm{voice}}
=
\texttt{voice\_service\_protection}.
\label{eq:voice_protection_objective}
\end{equation}

三类目标的优先级关系为：

\begin{equation}
\begin{aligned}
P_{\mathrm{priority}}
=
\{
&\operatorname{Primary}
(G_{\mathrm{video}}),
\\
&\operatorname{Secondary}
(G_{\mathrm{energy}}),
\\
&\operatorname{Mandatory}
(G_{\mathrm{voice}})
\}.
\end{aligned}
\label{eq:translated_objective_priority}
\end{equation}

其中，视频上行保障为主要目标，
降低RAN能耗为次级优化目标，
语音业务保护为必须满足的约束。
因此，节能优化不能以违反视频SLA或降低语音业务质量为代价。

本文采用固定的演唱会上行保障SLA模板，
并通过配置引用获取具体门限。
视频用户是否满足吞吐率要求定义为：

\begin{equation}
\mathbb{I}_u
=
\mathbb{I}
\left[
R_u^{\mathrm{UL}}
\geq
R_{\mathrm{th}}
\right],
\label{eq:video_user_threshold_indicator}
\end{equation}

其中，
$R_u^{\mathrm{UL}}$表示视频用户$u$的上行吞吐率，
$R_{\mathrm{th}}$表示单用户吞吐率门限。

目标视频用户达标比例为：

\begin{equation}
\rho_{\mathrm{video}}
=
\frac{1}
{\left|U_{\mathrm{video}}\right|}
\sum_{u\in U_{\mathrm{video}}}
\mathbb{I}_u.
\label{eq:translated_video_satisfaction_ratio}
\end{equation}

本文配置要求：

\begin{equation}
R_{\mathrm{th}}
=
20~\mathrm{Mbps},
\qquad
\rho_{\mathrm{video}}
\geq
0.95.
\label{eq:translated_video_throughput_sla}
\end{equation}

即至少95\%的目标视频用户上行吞吐率不低于20 Mbps。

对于视频上行时延，
采用用户级P95统计值：

\begin{equation}
D_{\mathrm{video}}^{P95}
=
Q_{0.95}
\left(
\left\{
D_u^{\mathrm{UL}}
\mid
u\in U_{\mathrm{video}}
\right\}
\right),
\label{eq:translated_video_delay_p95}
\end{equation}

并要求：

\begin{equation}
D_{\mathrm{video}}^{P95}
\leq
30~\mathrm{ms}.
\label{eq:translated_video_delay_sla}
\end{equation}

对于语音业务，
首先要求策略实施后的语音质量满足：

\begin{equation}
Q_{\mathrm{voice}}
\geq
0.95.
\label{eq:translated_voice_quality_sla}
\end{equation}

同时定义语音质量相对于基线的下降量：

\begin{equation}
\Delta Q_{\mathrm{voice}}
=
\max
\left(
0,
Q_{\mathrm{voice}}^{0}
-
Q_{\mathrm{voice}}
\right),
\label{eq:translated_voice_degradation}
\end{equation}

其中，
$Q_{\mathrm{voice}}^{0}$表示策略实施前的语音质量基线。

语音质量下降需要满足：

\begin{equation}
\Delta Q_{\mathrm{voice}}
\leq
0.02.
\label{eq:translated_voice_degradation_sla}
\end{equation}

为避免策略过度占用无线资源，
策略实施后的PRB利用率还需要满足：

\begin{equation}
\rho_{\mathrm{PRB}}
\leq
0.90.
\label{eq:translated_prb_sla}
\end{equation}

因此，本文业务意图转译形成的硬约束集合为：

\begin{equation}
C_{\mathrm{SLA}}
=
\left\{
\begin{aligned}
&\rho_{\mathrm{video}}\geq0.95,\\
&D_{\mathrm{video}}^{P95}\leq30~\mathrm{ms},\\
&Q_{\mathrm{voice}}\geq0.95,\\
&\Delta Q_{\mathrm{voice}}\leq0.02,\\
&\rho_{\mathrm{PRB}}\leq0.90.
\end{aligned}
\right.
\label{eq:translated_sla_set}
\end{equation}

上述门限由仿真配置提供，
用于验证策略生成和策略评估流程。

    \item 存在视频保障目标时，
    保留视频用户达标比例和P95时延约束；
    \item 存在语音保护目标时，
    保留语音绝对质量和相对下降约束；
    \item PRB利用率上限约束始终保留。
\end{itemize}

意图抽取阶段生成的待解析项，
在转译过程中根据外部数据补全情况进行更新。
例如，事件记录匹配成功后，
可以消除准确活动时间待解析项；
场馆映射成功后，
可以消除RAN作用范围待解析项；
SLA模板解析成功后，
可以消除业务门限待解析项。

设转译后仍未解决的阻断项集合为：

\begin{equation}
U_{\mathrm{blocking}}
=
\left\{
u
\in
U_{\mathrm{unresolved}}
\mid
Severity(u)
=
\texttt{blocking}
\right\}.
\label{eq:translation_blocking_items_reduced}
\end{equation}

转译状态定义为：

\begin{equation}
Z_{\mathrm{status}}
=
\begin{cases}
\texttt{ready},
&
U_{\mathrm{blocking}}
=
\varnothing,
\\[2mm]
\texttt{blocked},
&
U_{\mathrm{blocking}}
\neq
\varnothing.
\end{cases}
\label{eq:translation_status_reduced}
\end{equation}

只有当：

\begin{equation}
Z_{\mathrm{status}}
=
\texttt{ready}
\label{eq:translation_ready_reduced}
\end{equation}

时，
转译结果才允许进入网络策略生成阶段。

经过业务意图转译后，
系统完成：

\begin{equation}
\text{结构化业务语义}
\longrightarrow
\text{RAN作用范围}
\longrightarrow
\text{RAN目标}
\longrightarrow
\text{SLA与资源约束}.
\label{eq:structured_intent_to_ran_requirement}
\end{equation}

\section{网络策略生成}
\label{sec:network_policy_generation}

业务意图转译完成后，
系统已经获得策略生效时间、目标小区、目标用户规则、
RAN目标、SLA约束及其优先级关系。
网络策略生成的任务是将上述RAN需求转换为
多个动作组合和参数配置不同的候选策略，
为后续性能评估和策略排序提供输入。

本文当前的初始策略生成过程可表示为：

\begin{equation}
I_{\mathrm{trans}}^{\mathrm{RAN}}
+
\mathcal{T}
+
\boldsymbol{\Theta}
+
\mathcal{C}_{\mathrm{static}}
\longrightarrow
\mathcal{P}^{(0)},
\label{eq:initial_policy_generation_reduced}
\end{equation}

其中，
$I_{\mathrm{trans}}^{\mathrm{RAN}}$表示业务意图转译结果，
$\mathcal{T}$表示策略模板集合，
$\boldsymbol{\Theta}$表示离散动作参数空间，
$\mathcal{C}_{\mathrm{static}}$表示静态能力、冲突和资源约束，
$\mathcal{P}^{(0)}$表示初始候选策略集合。

需要说明的是，
当前初始策略生成器不直接读取RAN运行状态。
当前小区负载、用户吞吐率、时延、语音质量和能耗等状态，
将在后续候选策略评估阶段用于计算策略实施效果。

\subsection*{离散参数组合}

策略模板只确定候选策略包含哪些动作，
还需要为每个动作赋予具体参数。

设：

\begin{itemize}
    \item $\Theta_r$表示视频PRB预留比例集合；
    \item $\Theta_w$表示视频调度权重集合；
    \item $\Theta_v$表示语音最低PRB比例集合；
    \item $\Theta_e$表示节能强度集合。
\end{itemize}

完整离散动作空间可表示为：

\begin{equation}
\boldsymbol{\Theta}
=
\Theta_r
\times
\Theta_w
\times
\Theta_v
\times
\Theta_e.
\label{eq:discrete_policy_parameter_space}
\end{equation}

对于某个具体策略模板，
系统只对该模板包含的动作参数执行笛卡尔积组合。

设模板$T_k$包含$J_k$个动作，
对应参数集合为：

\begin{equation}
\Theta_{k,1},
\Theta_{k,2},
\ldots,
\Theta_{k,J_k},
\end{equation}

则该模板的候选参数组合为：

\begin{equation}
\Omega_k
=
\Theta_{k,1}
\times
\Theta_{k,2}
\times
\cdots
\times
\Theta_{k,J_k}.
\label{eq:template_parameter_cartesian_product}
\end{equation}

例如，联合保障与语音保护模板的参数空间为：

\begin{equation}
\Omega_{\mathrm{joint+voice}}
=
\Theta_r
\times
\Theta_w
\times
\Theta_v.
\label{eq:joint_voice_parameter_space}
\end{equation}

若同时加入节能动作，则参数空间扩展为：

\begin{equation}
\Omega_{\mathrm{joint+voice+energy}}
=
\Theta_r
\times
\Theta_w
\times
\Theta_v
\times
\Theta_e.
\label{eq:joint_voice_energy_parameter_space}
\end{equation}

当前实现通过离散笛卡尔积穷举模板内的参数组合，
生成不同参数配置的候选策略。
该过程不使用随机采样，
同一输入和同一配置下生成结果保持一致。


\subsection*{静态约束过滤与候选控制}

笛卡尔积生成的动作组合中，
可能存在参数非法、动作冲突或资源明显超限的策略。
因此，候选策略进入性能评估前，
需要执行静态约束过滤。

当前过滤内容包括：

\begin{enumerate}[label=\arabic*)]
    \item 动作类型不能重复；
    \item 动作必须存在于当前动作库；
    \item 动作参数必须满足预定义Schema；
    \item 参数值必须属于配置允许的离散集合；
    \item 动作作用对象必须与当前目标小区和用户规则一致；
    \item 同一策略中不能存在预定义冲突动作；
    \item 视频和语音资源比例不能明显超过静态资源上限。
\end{enumerate}

对于视频PRB预留比例$r$
和语音最低PRB保护比例$v$，
当前采用以下静态资源约束：

\begin{equation}
r+v
\leq
\rho_{\mathrm{PRB}}^{\max},
\label{eq:static_prb_constraint_reduced}
\end{equation}

其中，
$\rho_{\mathrm{PRB}}^{\max}$为配置中的最大PRB利用率。

该约束只用于生成阶段的静态检查，
并不表示策略实施后的实际PRB利用率一定满足要求。
策略后的实际PRB利用率需要在候选策略评估阶段，
结合当前RAN状态重新计算。

当前还设置了部分动作冲突规则。
例如：

\begin{itemize}
    \item 存在语音保护目标时，
    高视频调度权重策略需要同时包含语音保护动作；
    \item 最大PRB预留比例和最大节能强度不能同时使用。
\end{itemize}

上述规则用于提前删除明显不协调的动作组合。

通过静态检查的候选策略还需要进行内容去重。
系统根据动作类型、作用对象和参数构造规范化策略签名：

\begin{equation}
Signature(P_i)
=
\operatorname{Canonical}
\left(
A_i
\right).
\label{eq:policy_signature_reduced}
\end{equation}

若两个候选策略具有相同动作类型、目标和参数，则：

\begin{equation}
Signature(P_i)
=
Signature(P_j),
\label{eq:duplicate_policy_reduced}
\end{equation}

系统只保留稳定顺序中首次出现的策略。

候选策略按照模板优先级、模板标识和参数顺序进行稳定排序，
并按最终顺序生成策略标识：

\begin{equation}
PolicyId_i
=
\texttt{RAN-POLICY-R}
\Vert n
\Vert
\texttt{-}
\Vert i,
\label{eq:policy_identifier_reduced}
\end{equation}

其中，
$n$表示生成轮次，
$i$表示当前轮中的候选序号。

为控制单轮计算规模，
系统设置最大候选数量：

\begin{equation}
\left|
\mathcal{P}^{(n)}
\right|
\leq
N_{\max}.
\label{eq:maximum_policy_count_reduced}
\end{equation}

当通过过滤的候选数超过上限时，
当前实现按照稳定顺序保留前$N_{\max}$个策略：

\begin{equation}
\mathcal{P}_{\mathrm{retained}}
=
\operatorname{Prefix}
\left(
\mathcal{P}_{\mathrm{valid}},
N_{\max}
\right).
\label{eq:policy_prefix_truncation_reduced}
\end{equation}

最终得到初始候选策略集合：

\begin{equation}
\mathcal{P}^{(0)}
=
\left\{
P_1^{(0)},
P_2^{(0)},
\ldots,
P_M^{(0)}
\right\}.
\label{eq:initial_policy_set_reduced}
\end{equation}

经过网络策略生成，
系统完成：

\begin{equation}
\text{RAN目标与约束}
\longrightarrow
\text{动作模板}
\longrightarrow
\text{离散参数组合}
\longrightarrow
\text{静态可用候选策略}.
\label{eq:ran_requirement_to_candidate_policies}
\end{equation}

\section{候选策略评估}
\label{sec:candidate_policy_evaluation}

网络策略生成阶段得到多个动作组合和参数配置不同的候选策略。
这些候选策略在视频业务保障效果、语音业务影响、
无线资源占用、RAN能耗和潜在风险等方面存在差异，
因此需要结合当前RAN状态进行统一评估。

本文候选策略评估过程包括性能计算、
硬约束检查、多目标评分、策略排序和反馈优化，
其总体过程可表示为：

\begin{equation}
\left(
X_{\mathrm{RAN}},
P_i
\right)
\xrightarrow{\mathrm{Performance\ Evaluation}}
Z_i
\xrightarrow{\mathrm{Constraint\ Check}}
H_i
\xrightarrow{\mathrm{Scoring}}
S_i
\xrightarrow{\mathrm{Feedback}}
\mathcal{N}(P_i),
\label{eq:policy_evaluation_flow_reduced}
\end{equation}

其中，
$X_{\mathrm{RAN}}$表示当前RAN状态，
$P_i$表示第$i$个候选策略，
$Z_i$表示策略实施后的性能结果，
$H_i$表示硬约束检查结果，
$S_i$表示多目标评分结果，
$\mathcal{N}(P_i)$表示反馈生成的局部策略邻域。

\texttt{simplified-ran-v1}

设候选策略包含的主要动作参数为：

\label{eq:voice_degradation_eval_reduced}
\end{equation}

策略实施后的RAN能耗为：

\begin{equation}
E'
=
\operatorname{clip}
\left[
E_0
\left(
1-\eta_ee
+
\eta_u\max(0,u'-u_0)
+
\eta_aN_{\mathrm{highcost}}
\right),
E_{\min},
E_{\max}
\right],
\label{eq:ran_energy_reduced}
\end{equation}

其中，
$\eta_e$表示节能动作带来的能耗下降，
$\eta_u$表示资源利用率增加导致的能耗增长，
$\eta_a$表示高开销动作的附加能耗，
$N_{\mathrm{highcost}}$表示高开销动作数量。


\subsubsection*{风险计算}

本文综合考虑PRB过载、语音质量下降、
节能强度、动作复杂度、普通用户性能下降和BLER恶化风险。

综合风险表示为：

\begin{equation}
R
=
\operatorname{clip}
\left(
\omega_uR_u
+
\omega_qR_q
+
\omega_eR_e
+
\omega_aR_a
+
\omega_fR_f
+
\omega_bR_b,
0,
1
\right),
\label{eq:total_risk_reduced}
\end{equation}

其中：

\begin{itemize}
    \item $R_u$表示PRB过载风险；
    \item $R_q$表示语音质量风险；
    \item $R_e$表示节能动作风险；
    \item $R_a$表示动作复杂度风险；
    \item $R_f$表示普通用户公平性风险；
    \item $R_b$表示视频BLER风险；
    \item $\omega_{\cdot}$表示相应风险权重。
\end{itemize}


\subsection*{硬约束检查与多目标评分}

性能模型完成策略效果计算后，
系统对每个候选策略执行硬约束检查。

当前硬约束集合为：

\begin{equation}
\left\{
\begin{aligned}
&\rho_T\geq0.95,\\
&D_{P95}\leq30~\mathrm{ms},\\
&Q'\geq0.95,\\
&\Delta Q_{\mathrm{voice}}\leq0.02,\\
&u'\leq0.90.
\end{aligned}
\right.
\label{eq:hard_constraints_reduced}
\end{equation}

设第$j$项硬约束的满足函数为：

\begin{equation}
c_j(P_i)
=
\begin{cases}
1,
& P_i\text{满足第$j$项约束},\\
0,
& P_i\text{违反第$j$项约束}.
\end{cases}
\label{eq:constraint_indicator_reduced}
\end{equation}

候选策略的总体可行性为：

\begin{equation}
H(P_i)
=
\prod_{j=1}^{J}
c_j(P_i).
\label{eq:policy_feasibility_reduced}
\end{equation}

硬约束检查器会遍历全部约束，
保留所有违约原因，
而不是在发现第一项违约后停止。

对于不可行策略：

\begin{equation}
H(P_i)=0
\quad\Longrightarrow\quad
Score(P_i)=0,
\qquad
Rank(P_i)=\varnothing.
\label{eq:infeasible_policy_reduced}
\end{equation}

因此，节能收益和资源效率不能补偿视频SLA、
语音保护或PRB资源上限违约。

对于可行策略，
系统采用固定上下界归一化指标。

增益型指标归一化为：

\begin{equation}
N_g(x)
=
\operatorname{clip}
\left(
\frac{x-x_{\min}}
{x_{\max}-x_{\min}},
0,
1
\right),
\label{eq:gain_normalization_reduced}
\end{equation}

成本型指标归一化为：

\begin{equation}
N_c(x)
=
1-N_g(x).
\label{eq:cost_normalization_reduced}
\end{equation}

业务保障评分为：

\begin{equation}
\begin{aligned}
S_{\mathrm{service}}
={}&
0.35N_g(\rho_T)
+
0.20N_g(T_{P05})
+
0.20N_c(D_{P95})
\\
&+
0.10N_c(\overline{B})
+
0.15N_g(Q').
\end{aligned}
\label{eq:service_score_reduced}
\end{equation}

节能收益为：

\begin{equation}
G_E
=
\frac{
E_0-E'
}{
E_0
},
\label{eq:energy_gain_reduced}
\end{equation}

节能评分为：

\begin{equation}
S_{\mathrm{energy}}
=
N_g(G_E).
\label{eq:energy_score_reduced}
\end{equation}

资源评分为：

\begin{equation}
S_{\mathrm{resource}}
=
0.80N_c(u')
+
0.20N_c(N_{\mathrm{actions}}).
\label{eq:resource_score_reduced}
\end{equation}

风险评分为：

\begin{equation}
S_{\mathrm{risk}}
=
N_c(R).
\label{eq:risk_score_reduced}
\end{equation}

候选策略的综合评分为：

\begin{equation}
Score(P_i)
=
0.60S_{\mathrm{service}}
+
0.15S_{\mathrm{energy}}
+
0.15S_{\mathrm{resource}}
+
0.10S_{\mathrm{risk}}.
\label{eq:total_score_reduced}
\end{equation}

当前可行策略首先按照综合评分降序排序。
当多个策略综合评分相同时，
依次优先选择：

\begin{enumerate}[label=\arabic*)]
    \item PRB利用率更低的策略；
    \item 综合风险更低的策略；
    \item RAN能耗更低的策略；
    \item 动作数量更少的策略；
    \item 策略标识字典序更小的策略。
\end{enumerate}

排序键可表示为：

\begin{equation}
K(P_i)
=
\left(
-Score(P_i),
u_i',
R_i,
E_i',
N_{\mathrm{actions},i},
ID_i
\right).
\label{eq:ranking_key_reduced}
\end{equation}


\subsection*{反馈优化与终止机制}

候选策略评估结果用于生成下一轮局部候选策略。
本文采用单父策略、相邻参数档位和单操作邻域搜索。

设第$n$轮选中的父策略为
$P_{\mathrm{parent}}^{(n)}$，
则下一轮候选集合为：

\begin{equation}
\mathcal{P}^{(n+1)}
=
\mathcal{N}
\left(
P_{\mathrm{parent}}^{(n)},
F^{(n)}
\right),
\label{eq:feedback_neighborhood_reduced}
\end{equation}

其中，
$F^{(n)}$表示第$n$轮的性能结果和违约信息。

当当前轮存在可行策略时，
系统选择排名第1的策略作为父策略。
当当前轮不存在可行策略时，
根据业务评分、资源评分、风险评分、
PRB利用率和策略标识选择相对较优的父策略。

动作参数均来自有序离散集合。
参数更新采用相邻档位调整：

\begin{equation}
\theta^{(n+1)}
=
\operatorname{NextAllowed}
\left(
\theta^{(n)},
d
\right),
\qquad
d\in\{-1,+1\}.
\label{eq:adjacent_parameter_reduced}
\end{equation}

当前主要反馈规则如表
\ref{tab:feedback_rules_reduced}
所示。

        \\

        \\

同一轮反馈中的不同调整操作分别生成独立候选，
而不是一次性合并到同一策略中。
所有反馈候选仍需重新经过静态约束检查。

当反馈关闭时，
系统只执行第0轮策略生成和评估，
随后终止：

\begin{equation}
feedbackEnabled
=
\texttt{false}
\quad\Longrightarrow\quad
generationRounds=1.
\label{eq:feedback_disabled_reduced}
\end{equation}

当反馈开启时，
主要终止条件包括：

\begin{enumerate}[label=\arabic*)]
    \item 当前最优策略总分达到配置门限；
    \item 连续若干轮最优分提升低于最小改进阈值；
    \item 达到最大反馈迭代次数；
    \item 当前父策略无法生成新的有效候选。
\end{enumerate}

评分门限条件为：

\begin{equation}
\max_{P_i\in\mathcal{P}^{(n)}}
Score(P_i)
\geq
Score_{\mathrm{th}}.
\label{eq:score_threshold_stop_reduced}
\end{equation}

收敛条件为：

\begin{equation}
\left|
Score_{\max}^{(n)}
-
Score_{\max}^{(n-1)}
\right|
<
\varepsilon_{\mathrm{score}}.
\label{eq:score_convergence_reduced}
\end{equation}

整个反馈过程中不允许放宽视频、语音和PRB硬约束。
在配置允许时，
系统只可以取消节能这一软优化目标。

经过候选策略评估，
系统完成：

\begin{equation}
\text{候选策略}
\longrightarrow
\text{性能计算}
\longrightarrow
\text{硬约束判定}
\longrightarrow
\text{多目标评分与排序}
\longrightarrow
\text{局部反馈优化}.
\label{eq:candidate_policy_to_ranked_policy}
\end{equation}

实验覆盖业务意图抽取、业务意图转译、

当前仿真采用版本化配置文件统一管理SLA门限、

    \end{tabular}
\end{table}

五组权重方案下的首名策略均保持不变，
说明当前首名策略对评分权重具有一定稳定性。

业务保障优先方案的Spearman相关系数为0.9824，
共有8个策略发生排名变化，
但Top-5候选集合未改变。

资源效率优先方案的Top-5 Jaccard相似度为0.6667，
Spearman相关系数为0.9604，
共有7个策略发生排名变化，
说明资源评分权重对前列候选策略的影响相对更明显。

节能优先和风险控制优先方案下，
完整排序未发生变化。
这表明在当前候选策略和性能结果中，
节能评分和风险评分的差异尚不足以改变策略相对次序。

不同权重方案下的综合分值不宜直接横向比较，
因为分值变化可能来自偏好权重调整，
而不是策略物理性能发生变化。


\subsection*{模型裁剪分析}

为保证性能指标位于预定义范围内，
简化RAN性能模型对部分输出执行边界裁剪：

\begin{equation}
x'
=
\operatorname{clip}
\left(
x_{\mathrm{raw}},
x_{\min},
x_{\max}
\right).
\label{eq:model_clipping_reduced}
\end{equation}

正式实验共记录4633次裁剪事件，
包括：

\begin{itemize}
    \item 风险归一化裁剪3644次，占78.65\%；
    \item 语音质量裁剪725次；
    \item 视频用户BLER裁剪264次。
\end{itemize}

其中：

\begin{equation}
3644+725+264=4633.
\label{eq:clipping_count_reduced}
\end{equation}

风险裁剪主要发生在风险原始值低于归一化下界时；
语音质量裁剪主要发生在原始结果高于1时；
BLER裁剪主要发生在原始结果低于0时。

对裁剪前后结果进行比较后发现：

\begin{equation}
N_{\mathrm{constraint\ change}}=0,
\label{eq:clipping_constraint_change_reduced}
\end{equation}

即没有候选策略因裁剪导致硬约束判定发生变化。

同时：

\begin{equation}
N_{\mathrm{top\ change}}=0,
\label{eq:clipping_top_change_reduced}
\end{equation}

即裁剪没有改变各轮首名策略和最终推荐策略。

因此，本次实验中的裁剪没有影响硬约束结论和最终推荐结果，
但较多的风险归一化裁剪说明，
当前简化模型的部分边界和系数仍需要进一步标定。

\chapter{网络高精度孪生建模与编排}
\label{sec:high_fidelity_twin_overview}

网络数字孪生是在数字空间中构建物理网络虚拟映射体，
并利用网络数据、模型和映射关系描述网络实体、
运行状态、控制行为及性能变化的技术。
对于意图驱动网络决策而言，
候选策略在下发物理网络之前，
需要在与当前网络状态相对应的孪生环境中进行推演和验证，
以降低在线试错带来的业务风险。

网络数字孪生的基本过程可以表示为：

\begin{equation}
\mathcal{N}_{\mathrm{P}}
\xrightarrow{\mathrm{Data\ Acquisition}}
D(t)
\xrightarrow{\mathrm{Twin\ Modeling}}
\mathcal{N}_{\mathrm{T}}(t)
\xrightarrow{\mathrm{Simulation}}
\hat{\boldsymbol{Y}}(t),
\label{eq:physical_to_twin_overview}
\end{equation}

其中，
$\mathcal{N}_{\mathrm{P}}$表示物理网络，
$D(t)$表示时刻$t$获取的网络数据，
$\mathcal{N}_{\mathrm{T}}(t)$表示数字孪生状态，
$\hat{\boldsymbol{Y}}(t)$表示孪生环境输出的性能预测结果。

本文面向单小区RAN候选策略验证场景，
将网络数字孪生表示为：

\begin{equation}
\mathcal{N}_{\mathrm{T}}(t)
=
\left\{
D(t),
M,
X_{\mathrm{T}}(t),
\Gamma
\right\},
\label{eq:network_twin_composition}
\end{equation}

其中：

\begin{itemize}
    \item $D(t)$表示用于构建孪生状态的网络状态和业务数据；
    \item $M$表示实体、资源、行为和性能模型集合；
    \item $X_{\mathrm{T}}(t)$表示孪生环境中的网络状态；
    \item $\Gamma$表示物理网络对象、候选策略与孪生对象之间的映射关系。
\end{itemize}

本文中的网络高精度孪生建模主要解决：

\begin{equation}
\text{如何围绕候选策略验证任务准确表示网络状态、实体关系和性能行为}.
\end{equation}

孪生环境编排主要解决：

\begin{equation}
\text{如何根据候选策略自动组织状态、模型、场景和验证任务}.
\end{equation}

两者之间的关系可以表示为：

\begin{equation}
\begin{aligned}
\mathcal{N}_{\mathrm{P}}
&\xrightarrow{\mathrm{Twin\ Modeling}}
\mathcal{N}_{\mathrm{T}},
\\
P_i
&\xrightarrow{\mathrm{Twin\ Orchestration}}
\mathcal{E}_i
\xrightarrow{\mathrm{Twin\ Validation}}
V_i,
\end{aligned}
\label{eq:modeling_orchestration_validation_relation}
\end{equation}

其中，
$P_i$表示第$i$个候选RAN策略，
$\mathcal{E}_i$表示针对该策略构建的独立孪生验证场景，
$V_i$表示对应的策略验证结果。

从端到端流程看，
本章与第三章的关系为：

\begin{equation}
\begin{aligned}
\text{Business Intent}
&\xrightarrow{\mathrm{Intent\ Decision}}
\mathcal{P}_{\mathrm{candidate}}
\\
&\xrightarrow{\mathrm{Twin\ Orchestration}}
\left\{
\mathcal{E}_1,
\ldots,
\mathcal{E}_N
\right\}
\\
&\xrightarrow{\mathrm{Twin\ Validation}}
\mathcal{P}_{\mathrm{validated}}.
\end{aligned}
\label{eq:intent_to_twin_validation_flow}
\end{equation}

其中，
$\mathcal{P}_{\mathrm{candidate}}$表示第三章生成的候选策略集合，
$\mathcal{P}_{\mathrm{validated}}$表示经过数字孪生推演、
硬约束检查和综合评分后的策略集合。

本章的总体技术流程为：

\begin{equation}
\begin{aligned}
\text{RAN State}
&\xrightarrow{\mathrm{Twin\ State\ Construction}}
\text{Twin State}
\\
\text{Candidate Policies}

\text{Predictions}
\\

\end{equation}

本文所称“高精度”并不表示当前原型已经达到实网级预测精度，
而是指孪生模型能够围绕特定验证任务，
在状态表达、对象映射、模型组合、场景隔离和结果追踪等方面
提供较完整、可验证和可复现的支撑能力。

高精度可从以下维度综合描述：

\begin{equation}
Q_{\mathrm{twin}}
=
f
\left(
Q_{\mathrm{state}},
Q_{\mathrm{prediction}},
Q_{\mathrm{scenario}},
Q_{\mathrm{trace}}
\right),
\label{eq:twin_quality_dimensions_overview}
\end{equation}

其中，
$Q_{\mathrm{state}}$表示状态表达完整性，
$Q_{\mathrm{prediction}}$表示性能预测准确性，
$Q_{\mathrm{scenario}}$表示场景对验证任务的覆盖程度，
$Q_{\mathrm{trace}}$表示模型版本、输入和执行过程的可追踪程度。

当前P0原型重点实现状态构建、语义建模、场景编排、
性能模型封装和策略验证，
实时状态同步、在线参数校准和数据驱动残差修正

\section{网络高精度孪生建模}
\label{sec:high_fidelity_twin_modeling}

网络高精度孪生建模的目标是在数字空间中构建
能够描述物理RAN实体、当前状态、业务对象、
无线资源和性能变化的可计算模型，
为候选策略编排和验证提供统一基础。

本文面向演唱会场景下的单小区RAN策略验证，
主要关注视频业务保障、语音业务保护、
无线资源竞争和RAN节能等过程。

孪生建模过程表示为：

\begin{equation}
D_{\mathrm{RAN}}
\xrightarrow{\mathrm{State\ Construction}}
X_{\mathrm{T}}
\xrightarrow{\mathrm{Semantic\ Modeling}}
G_{\mathrm{RAN}}
\xrightarrow{\mathrm{Model\ Registration}}

其中，

$\mathcal{M}_{\mathrm{twin}}$表示面向策略验证的模型集合。


\subsection*{孪生建模对象与模型体系}

网络数字孪生并不是对物理网络全部细节进行无差别复制，
而是根据候选策略验证任务选择必要对象和状态变量。

本文的建模对象包括：

\begin{itemize}
    \item 网络实体：gNB、小区、载波和调度器；
    \item 业务对象：视频用户组、语音用户组和普通用户组；
    \item 无线资源：PRB资源及其利用状态；
    \item 控制行为：PRB预留、调度权重调整、语音资源保护和节能控制；
    \item 性能指标：视频吞吐率、时延、BLER、语音质量、PRB利用率和RAN能耗。
\end{itemize}

设网络孪生模型集合为：

\begin{equation}
\mathcal{M}_{\mathrm{twin}}
=
\left\{
M_{\mathrm{entity}},
M_{\mathrm{state}},
M_{\mathrm{resource}},
M_{\mathrm{behavior}},
M_{\mathrm{service}},
M_{\mathrm{performance}}
\right\},
\label{eq:twin_model_system}
\end{equation}

其中：

\begin{itemize}
    \item $M_{\mathrm{entity}}$描述网络实体及其属性；
    \item $M_{\mathrm{state}}$描述当前RAN运行状态；
    \item $M_{\mathrm{resource}}$描述无线资源及分配关系；
    \item $M_{\mathrm{behavior}}$描述调度和控制动作；
    \item $M_{\mathrm{service}}$描述不同业务对象及其约束；
    \item $M_{\mathrm{performance}}$描述状态和策略到性能指标的映射。
\end{itemize}

不同模型之间存在依赖关系，例如：

\begin{equation}
M_{\mathrm{resource}}
\rightarrow
M_{\mathrm{behavior}}
\rightarrow
M_{\mathrm{performance}}.
\label{eq:model_dependency_chain}
\end{equation}

因此，本文通过模型注册表保存模型类型、版本、
支持指标和依赖关系，
根据候选策略验证需求选择所需模型，
而不是使用单一模型描述所有网络过程。

本文当前原型直接复用第三章已有的
\texttt{RANState}作为基础网络状态真值，

其中：

后续可结合实际网络测量数据进一步扩展。

\section{孪生模型校准方法}
\label{sec:twin_model_calibration}

由于无线环境、业务负载和调度过程具有动态性，
孪生性能模型与真实网络行为之间可能存在偏差。
因此，在具备实际网络观测数据后，
需要对孪生模型参数进行校准。

设孪生模型为：

\begin{equation}
\hat{\boldsymbol{Y}}
=
f_{\mathrm{twin}}
\left(
X,
P;
\boldsymbol{\theta}
\right),
\label{eq:twin_model_calibration_model}
\end{equation}

真实网络或高保真仿真观测为$\boldsymbol{Y}$，
则模型误差为：

\begin{equation}
\boldsymbol{e}
=
\boldsymbol{Y}
-
\hat{\boldsymbol{Y}}.
\label{eq:twin_model_error}
\end{equation}

模型校准的目标是寻找参数$\boldsymbol{\theta}^{*}$，
使得多个样本上的预测误差最小：

\begin{equation}
\boldsymbol{\theta}^{*}
=
\arg\min_{\boldsymbol{\theta}}
\sum_{n=1}^{N}
\mathcal{L}
\left(
\boldsymbol{Y}^{(n)},
f_{\mathrm{twin}}
\left(
X^{(n)},
P^{(n)};
\boldsymbol{\theta}
\right)
\right).
\label{eq:twin_parameter_calibration}
\end{equation}

其中，
$\mathcal{L}(\cdot)$表示多指标预测损失函数。


\subsection*{待校准参数}

面向本文RAN策略验证任务，
后续可重点校准：

\begin{itemize}
    \item 视频吞吐率模型参数；
    \item 视频时延模型参数；
    \item BLER模型参数；
    \item 语音质量模型参数；
    \item RAN能耗模型参数。
\end{itemize}

参数集合表示为：

\begin{equation}
\boldsymbol{\theta}
=
\left\{
\boldsymbol{\theta}_{R},
\boldsymbol{\theta}_{D},
\boldsymbol{\theta}_{B},
\boldsymbol{\theta}_{Q},
\boldsymbol{\theta}_{E}
\right\}.
\label{eq:twin_calibration_parameters}
\end{equation}


\subsection*{约束条件下的参数校准}

模型校准除了降低预测误差，
还需要满足参数边界和基本物理规律：

\begin{equation}
\boldsymbol{\theta}_{\min}
\leq
\boldsymbol{\theta}
\leq
\boldsymbol{\theta}_{\max}.
\label{eq:twin_parameter_bounds}
\end{equation}

同时，模型输出应满足：

\begin{equation}
\hat{R}\geq0,
\qquad
\hat{D}\geq0,
\qquad
0\leq\widehat{BLER}\leq1,
\label{eq:twin_output_bounds_one}
\end{equation}

\begin{equation}
0\leq
\hat{Q}_{\mathrm{voice}}
\leq1,
\qquad
0\leq
\hat{\rho}_{\mathrm{PRB}}
\leq1.
\label{eq:twin_output_bounds_two}
\end{equation}

还应保持必要的单调关系，例如：

\begin{equation}
\frac{\partial \hat{R}_{\mathrm{video}}}
{\partial r}
\geq0,
\qquad
\frac{\partial \hat{D}_{\mathrm{video}}}
{\partial \rho}
\geq0.
\label{eq:twin_monotonic_constraints}
\end{equation}

通过上述约束，
可以避免模型参数虽然降低了拟合误差，
但产生违反无线网络基本规律的预测结果。


\subsection*{当前实现边界}

当前P0原型的主要目标是验证：

\begin{equation}
\text{Policy}
\rightarrow
\text{Twin Scenario}
\rightarrow
\text{Prediction}
\rightarrow
\text{Validation}
\end{equation}

流程的正确性，
因此正式实验使用冻结的
\texttt{simplified-ran-v1}模型参数，
未执行参数搜索、在线校准和残差模型训练。

本节给出的校准方法属于后续精度增强方案。
在获得实网测量数据或高保真系统级仿真数据后，
可以在不改变当前孪生编排和验证框架的前提下，
引入参数校准和残差修正，
进一步提高孪生模型的预测能力。


\section{孪生环境中的策略编排}
\label{sec:twin_environment_orchestration}

孪生环境中的策略编排是将候选策略、
孪生状态、语义关系和模型注册信息
转换为可执行验证场景的过程。

本文将其表示为：

\begin{equation}
\mathcal{O}
:
\left(
P_i,
X_{\mathrm{T}},
G_{\mathrm{RAN}},
\mathcal{M}_{\mathrm{twin}}
\right)
\rightarrow
\mathcal{E}_i.
\label{eq:twin_orchestration_definition}
\end{equation}

其中，
$P_i$表示候选策略，
$X_{\mathrm{T}}$表示当前孪生状态，
$G_{\mathrm{RAN}}$表示网络语义图，
$\mathcal{M}_{\mathrm{twin}}$表示模型注册表，
$\mathcal{E}_i$表示策略对应的孪生验证场景。

本文策略编排主要包括：

\begin{enumerate}[label=\arabic*)]
    \item 候选策略适配；
    \item 策略与孪生实体映射；
    \item 模型与指标选择；
    \item 独立场景构建；
    \item 多策略顺序任务编排。
\end{enumerate}


\subsection*{候选策略适配}

第三章候选策略由多个动作组成，
策略适配器将其转换为统一控制向量：

\begin{equation}
P_i
\xrightarrow{\mathrm{Adapter}}
\boldsymbol{u}_i
=
\left[
r_i,
w_i,
v_i,
e_i
\right].
\label{eq:candidate_policy_adapter}
\end{equation}

当某类动作未出现在候选策略中时，
对应参数使用基础性能模型配置中定义的中性值，
而不是在适配器中硬编码默认参数。

适配过程校验：

\begin{itemize}
    \item 动作类型是否受支持；
    \item 同类动作是否重复；
    \item 参数是否缺失；
    \item 参数是否为有限数值；
    \item 参数是否满足定义范围；
    \item 策略目标小区是否与孪生状态一致。
\end{itemize}


\subsection*{策略与孪生实体映射}

策略参数需要映射到具体网络实体、
控制变量、性能模型和评价指标。

映射过程表示为：

\begin{equation}
P_i
\xrightarrow{\Gamma_{P}}
\left\{
V_i^{\mathrm{target}},
A_i^{\mathrm{control}},
M_i^{\mathrm{required}},
Y_i^{\mathrm{required}}
\right\},
\label{eq:policy_entity_model_mapping}
\end{equation}

其中：

\begin{itemize}
    \item $V_i^{\mathrm{target}}$表示策略作用实体；
    \item $A_i^{\mathrm{control}}$表示控制变量；
    \item $M_i^{\mathrm{required}}$表示所需模型；
    \item $Y_i^{\mathrm{required}}$表示待验证指标。
\end{itemize}

本文主要策略映射关系如表
\ref{tab:twin_policy_mapping}所示。

\begin{table}[htbp]
    \centering
    \caption{候选策略与孪生对象映射关系}
    \label{tab:twin_policy_mapping}
    \begin{tabular}{p{0.25\textwidth}p{0.20\textwidth}p{0.43\textwidth}}
        \toprule
        策略动作 & 控制变量 & 主要作用对象 \\
        \midrule
        视频资源预留
        & $r_i$
        & 小区、视频用户组、PRB资源
        \\

        \\

\subsection*{孪生验证场景构建}

针对候选策略$P_i$，
定义孪生验证场景：

\begin{equation}
\mathcal{E}_i
=
\left\{
X_i,
P_i,
\Gamma_i,
M_i,
Y_i,
T_i
\right\},
\label{eq:twin_validation_scenario}
\end{equation}

其中：

\begin{itemize}
    \item $X_i$表示独立孪生状态副本；
    \item $P_i$表示待验证策略；
    \item $\Gamma_i$表示策略映射结果；
    \item $M_i$表示选定模型；
    \item $Y_i$表示评价指标集合；
    \item $T_i$表示策略作用时间范围。
\end{itemize}

场景构建采用深拷贝机制，
满足：

\begin{equation}
\operatorname{Ref}(X_i)
\neq
\operatorname{Ref}(X_j),
\qquad
i\neq j,
\label{eq:twin_scenario_reference_isolation}
\end{equation}

并且：

\begin{equation}
\Delta X_i
\not\Rightarrow
\Delta X_j,
\qquad
\Delta X_i
\not\Rightarrow
\Delta X_{\mathrm{T}}.
\label{eq:twin_scenario_state_isolation}
\end{equation}

即修改任一候选策略场景，
不会影响其他场景或基础孪生状态。

每个场景均包含稳定的场景标识和内容哈希：

\begin{equation}
ID_{\mathrm{scenario},i}
=
g
\left(
ID_{\mathrm{snapshot}},
ID_{\mathrm{policy},i},
V_{\mathrm{model}}
\right).
\label{eq:twin_scenario_id}
\end{equation}

相同输入能够生成相同场景标识、
内容哈希和序列化结果。


\subsection*{多策略验证任务编排}

设候选策略集合为：

\begin{equation}
\mathcal{P}
=
\left\{
P_1,
P_2,
\ldots,
P_N
\right\}.
\end{equation}

对应的孪生任务集合为：

\begin{equation}
\mathcal{T}
=
\left\{
T_1,
T_2,
\ldots,
T_N
\right\}.
\end{equation}

当前P0原型采用顺序编排方式，
按照候选策略生成轮次、策略标识和原输入顺序
进行稳定排序：

\begin{equation}
T_1
\rightarrow
T_2
\rightarrow
\cdots
\rightarrow
T_N.
\label{eq:sequential_twin_orchestration}
\end{equation}

每个任务记录：

\begin{itemize}
    \item 策略和场景标识；
    \item 任务执行状态；
    \item 模型版本；
    \item 异常类型和错误摘要；
    \item 场景构建和执行轨迹。
\end{itemize}

任务状态包括：

\begin{equation}
\left\{
\texttt{succeeded},
\texttt{failed},
\texttt{timed\_out},
\texttt{skipped}
\right\}.
\end{equation}

当\texttt{failFast=false}时，
单任务失败不会阻断后续策略验证；
当\texttt{failFast=true}时，
首次失败或超时后，
其余未执行任务记为\texttt{skipped}。

当前编排器采用顺序执行，
多场景并行运行和计算资源动态调度
作为后续扩展方向。


\section{基于数字孪生的策略验证}
\label{sec:twin_based_policy_validation}

经过孪生状态构建和策略编排后，
每个候选策略被转换为独立、可执行的孪生验证场景。

策略验证过程表示为：

\begin{equation}
V_i
=
F_{\mathrm{val}}
\left(
\mathcal{E}_i
\right),
\label{eq:twin_validation_function}
\end{equation}

其执行链路为：

\begin{equation}
\mathcal{E}_i
\xrightarrow{\mathrm{Performance\ Evaluation}}
\hat{\boldsymbol{Y}}_i
\xrightarrow{\mathrm{Constraint\ Check}}
Feasible_i
\xrightarrow{\mathrm{Scoring}}
Score_i.
\label{eq:twin_validation_process}
\end{equation}


\subsection*{孪生环境性能推演}

当前P0原型采用第三章已有的
\texttt{SimplifiedRANPerformanceEvaluator}
作为基础可执行模型。

性能推演输入为：

\begin{equation}
I_i
=
\left(
X_i,
P_i,
V_{\mathrm{model}}
\right),
\end{equation}

输出为：

\begin{equation}
\hat{\boldsymbol{Y}}_i
=
\left\{
R_i,
D_i,
B_i,
Q_i,
\rho_i,
E_i
\right\},
\label{eq:twin_validation_metrics}
\end{equation}

其中：

\begin{itemize}
    \item $R_i$表示视频业务吞吐率；
    \item $D_i$表示视频业务时延；
    \item $B_i$表示视频上行BLER；
    \item $Q_i$表示语音业务质量；
    \item $\rho_i$表示PRB利用率；
    \item $E_i$表示RAN能耗。
\end{itemize}

孪生性能模型适配器直接调用原评估器，
并将原始性能结果包装为
\texttt{TwinPrediction}，
不执行二次计算、聚合、归一化或裁剪。

因此，关闭残差模型时：

\begin{equation}
\hat{\boldsymbol{Y}}_{i,\mathrm{twin}}
=
\hat{\boldsymbol{Y}}_{i,\mathrm{direct}}.
\label{eq:twin_direct_prediction_equal}
\end{equation}


\subsection*{业务约束满足判断}

策略验证需要判断性能结果是否满足
第三章意图转译阶段形成的SLA约束。

设硬约束集合为：

\begin{equation}
\mathcal{C}
=
\left\{
C_{\mathrm{video}},
C_{\mathrm{voice}},
C_{\mathrm{resource}},
C_{\mathrm{fairness}}
\right\}.
\label{eq:twin_hard_constraint_set}
\end{equation}

综合可行性表示为：

\begin{equation}
Feasible_i
=
\prod_{k}
\mathbb{I}
\left(
C_{i,k}
\right).
\label{eq:twin_policy_feasibility}
\end{equation}

其中：

\begin{itemize}
    \item $Feasible_i=1$表示满足全部硬约束；
    \item $Feasible_i=0$表示至少存在一个约束不满足。
\end{itemize}

本文的\texttt{TwinValidator}
不重新定义SLA门限和硬约束公式，
而是直接复用第三章已有的
\texttt{HardConstraintChecker}。

对于不可行策略：

\begin{equation}
Score_i=0,
\qquad
Rank_i=\varnothing.
\label{eq:twin_infeasible_policy_result}
\end{equation}

所有违约原因均保留在原始评分结果中。


\subsection*{多目标评分与排序}

对满足硬约束的策略，
本文复用第三章已有的
\texttt{PolicyScorer}
完成多目标评分与排序。

综合评分可以抽象表示为：

\begin{equation}
Score_i
=
F_{\mathrm{score}}
\left(
S_i^{\mathrm{service}},
S_i^{\mathrm{energy}},
S_i^{\mathrm{resource}},
S_i^{\mathrm{risk}}
\right),
\label{eq:twin_policy_score}
\end{equation}

其中：

\begin{itemize}
    \item $S_i^{\mathrm{service}}$表示业务保障评分；
    \item $S_i^{\mathrm{energy}}$表示节能评分；
    \item $S_i^{\mathrm{resource}}$表示资源利用评分；
    \item $S_i^{\mathrm{risk}}$表示风险评分。
\end{itemize}

最优策略为：

\begin{equation}
P^{*}
=
\arg\max_{P_i\in\mathcal{P}_{\mathrm{feasible}}}
Score_i.
\label{eq:twin_best_policy_selection}
\end{equation}

由于孪生验证直接复用第三章的约束、
归一化、评分和排序逻辑，
能够保证相同性能结果得到相同的可行性、
子评分、综合评分和排名。


\subsection*{执行失败与策略不可行的区分}

本文明确区分模型执行失败和策略不可行：

\begin{equation}
\text{Execution Failure}
\neq
\text{Policy Infeasibility}.
\label{eq:execution_failure_not_infeasible}
\end{equation}

模型执行失败或超时表示当前任务没有得到有效性能预测，
因此：

\begin{equation}
\text{Prediction}
=
\varnothing,
\qquad
\text{PolicyScore}
=
\varnothing.
\end{equation}

策略不可行表示模型已经成功执行，
但预测结果违反一个或多个硬约束，
此时保留完整性能结果、约束检查结果和违约原因。

该设计避免将系统异常错误地解释为策略性能不满足要求。


\subsection*{验证结果与后续优化}

数字孪生验证结果可以作为后续策略优化的输入，
例如根据视频吞吐率不足、语音质量下降或资源利用率过高
调整候选策略参数。

反馈闭环可表示为：

\begin{equation}
P_i
\rightarrow
V_i
\rightarrow
Feedback_i
\rightarrow
P_i^{\prime}.
\label{eq:twin_feedback_loop}
\end{equation}

当前P0原型已经生成结构化验证结果，
但尚未实现
\texttt{TwinValidationResult}
到第三章
\texttt{FeedbackOptimizer}
的正式适配和多轮反馈迭代。

因此，本文当前实现重点验证：

\begin{equation}
\text{Policy}
\rightarrow
\text{Twin Orchestration}
\rightarrow
\text{Twin Validation}
\end{equation}

闭环中的前向验证过程，
反馈优化作为后续扩展方向。


\section{仿真实现与结果分析}
\label{sec:twin_simulation_results}

为验证前述孪生状态构建、场景编排和策略验证方法，

实现了面向单小区RAN的轻量级数字孪生验证原型。

原型执行流程为：

\begin{equation}
\begin{aligned}

\texttt{simplified-ran-v1}，

\begin{itemize}
    \item 各场景中的孪生状态对象相互独立；
    \item 各场景中的候选策略对象相互独立；
    \item 修改任一场景不会影响其他场景；
    \item 修改任一场景不会影响基础孪生状态和原始策略。
\end{itemize}

场景隔离成功率为：

\begin{equation}
R_{\mathrm{isolation}}
=
\frac{100}{100}
=
100\%.
\end{equation}

\subsection*{故障隔离与可复现性}

实验分别注入场景构建失败、
模型执行失败和执行超时。

当\texttt{failFast=false}时，
单任务失败不会阻断其他策略验证；
当\texttt{failFast=true}时，
首次失败后停止后续任务，
未执行任务标记为\texttt{skipped}。

两种模式下均满足：

\begin{equation}
N_{\mathrm{fake\ prediction}}
=
N_{\mathrm{fake\ score}}
=
0.
\end{equation}

即失败或超时任务不会生成伪造的性能预测和策略评分。

在可复现性实验中，
相同输入和配置重复运行5次，
孪生状态、语义图、场景、预测、
验证结果和诊断信息的业务内容完全一致：

\begin{equation}
R_{\mathrm{repro}}
=
\frac{5}{5}
=
100\%.
\end{equation}

说明当前原型能够在固定输入和配置条件下，
稳定复现策略验证过程和业务输出。


\subsection*{结果讨论}

综合上述实验，
当前P0数字孪生原型已经实现：

\begin{enumerate}[label=\arabic*)]
    \item RAN状态到孪生状态的规范化构建；
    \item 网络实体、业务、资源和KPI的轻量语义建模；
    \item 候选策略到孪生实体、控制变量和模型的映射；
    \item 独立、可追踪和可复现的孪生场景构建；
    \item 基础性能模型的无损封装；
    \item 硬约束检查、多目标评分和策略排序；
    \item 单任务异常隔离和运行结果追踪。
\end{enumerate}

实验验证了：

\begin{equation}
\boxed{
\text{Candidate Policy}
\rightarrow
\text{Twin Orchestration}
\rightarrow
\text{Twin Validation}
}
\end{equation}

在当前单小区RAN原型中的可实现性。

但当前实验仍存在以下局限：

\begin{itemize}
    \item 仅面向单小区、单载波RAN；
    \item 基础性能模型为确定性简化模型；
    \item 尚未使用实网数据进行模型参数校准；
    \item 尚未启用数据驱动残差模型；
    \item 尚未实现验证结果到反馈优化器的闭环适配；
    \item 当前编排器仅支持顺序执行；
    \item 开销结果受当前硬件和文件系统环境影响。
\end{itemize}

后续可进一步引入实网测量或高保真仿真数据，
实现模型参数校准和残差修正，
并扩展多小区、并行编排和反馈优化能力，
逐步提高数字孪生对复杂RAN场景的预测能力和工程适用性。
